# DayZ Texture Tool 功能报告

> 软件版本：0.4.0 ｜ 技术栈：Python 3.10+ / PySide6 + qtawesome + Pillow + NumPy + blind-watermark ｜ 定位：DayZ 贴图格式转换桌面工具

---

## 1. 项目概况

DayZ Texture Tool 是一个面向 DayZ 模组作者的图形化贴图处理工具，解决"游戏打包贴图 ↔ 标准 PBR 贴图 ↔ DayZ 引擎贴图"之间的相互转换问题。软件为单窗口多页签（Tab）桌面程序，整体结构如下：

- **入口**：`src/dayz_texture_tool/__main__.py` → `app.py:main()` → `ui/shell.py:MainWindow`
- **UI 框架**：PySide6（Qt 6，Fusion 风格 + 自定义深/浅两套调色板），拖拽为 Qt 原生支持
- **图像处理**：Pillow（读写）+ NumPy（像素矩阵运算）
- **水印**：`blind-watermark` 盲水印库
- **外部工具**：DayZ Tools 自带的 `ImageToPAA.exe`（TGA/PNG 与游戏用的 `.paa` 互转，也用于把 PAA 输入解码回可读图片）
- **打包**：`PyInstaller`（`DayZ_Texture_Tool.spec`）+ `scripts/package.ps1` 一键构建可发布包
- **测试**：`tests/` 下 unittest 用例，覆盖各处理器与 UI 拖拽逻辑

六个页面（顶部导航切换）：**Game2PBR**、**PBR2DayZ**、**Watermark**、**SMDI**、**RVMAT**、**设置**。每个处理页都具备"选择图片 / 选择文件夹 / 拖拽 / 处理选中 / 处理全部 / 清除选中 / 全选 / 进度条 / 状态栏"这套通用交互。

## 2. Game2PBR 模块（游戏打包贴图 → PBR 通道拆分/重组）

**入口文件**：`processors/game2pbr.py`
**界面**：`ui/pages/game.py` 的 Game2PBR 页
**支持输入格式**：`.png .tga .tif .tiff .jpg .jpeg .bmp .dds`（见 `SUPPORTED_EXTENSIONS`）

该模块提供 **9 种处理器**，用户从下拉菜单选择当前处理器，然后对选中/拖入的图片执行对应转换。输出统一为 `.png`。

### 2.1 处理器清单

| 处理器 ID | 中文名 | 功能说明 | 输出文件 |
| ----------- | -------- | --------- | --------- |
| `DF_NRM` | 三角洲行动 NRM 贴图模式 | 解包 NRM：A 通道→金属度，B 通道→粗糙度，RG→法线 | `_Metal` / `_Rou` / `_N` |
| `DF_MRA` | 三角洲行动 MRA 贴图模式 | 解包 MRA：R→金属度，G→粗糙度，B→AO | `_met` / `_rou` / `_ao` |
| `ABI_ORN` | 暗区突围无限 ORN 贴图模式 | 解包 ORN：G→粗糙度，R→AO，BA→法线 | `_Rou` / `_AO` / `_N` |
| `SplitColorAlphaProcessor` | 颜色/透明通道拆分 | 把 RGBA 拆成"彩色 RGB（A 置 255）"和"灰度 Alpha"两张 | `_rgb` / `_alpha` |
| `SplitRGBAProcessor` | RGBA 四通道拆分 | 把 RGBA 各自拆成独立灰度图（R/G/B/A 共 4 张） | `_r` / `_g` / `_b` / `_a` |
| `MergeRGBAProcessor` | RGB 与透明通道合并 | 把彩色图与同名 `_a` 透明图合并为带 Alpha 的 RGBA（自动 LANCZOS 缩放对齐尺寸） | `_merged` |
| `XYNormalMapProcessor` | XY 法线贴图重建 | 由 XY 法线（RG 存储）按 `Nz = sqrt(1 - Nx² - Ny²)` 重建完整 XYZ 法线 | `_normal` |
| `DirectConvertProcessor` | 直接格式转换 | 原样复制像素，仅改格式/后缀（若输出名等于原名则自动加 `_converted` 防覆盖） | 自定义（默认空后缀） |
| `DirectinvertProcessor` | 直接反相处理 | 对 RGB 做反相 `1 - x`，并对 B 通道按 `sqrt(z)` 做特殊处理 | `_invert` |

> 注：`GAME2PBR_PROCESSORS` 字典还额外映射了别名 `SplitAllChannelsProcessor`、`BC5XYNormalMapProcessor`、`DirectInvertProcessor` 到上述同名函数，向下兼容不同命名约定。

### 2.2 模块级功能/开关

- **自定义后缀（Custom Suffixes）**：用户可输入逗号/空格/分号分隔的后缀列表，用于"选择文件夹批量处理"时按后缀自动识别该用哪个处理器（见 `batch.py:detect_game2pbr_processor`）。
- **生成贴图后缀（Output Suffixes）**：每种处理器可单独配置各输出通道的后缀（如把默认 `_Metal` 改成别的），界面动态渲染（`_render_game_output_suffixes`）。
- **匹配模式（Match Mode）**：`exact`（按后缀精确结尾匹配）/ `fuzzy`（子串包含匹配），控制自定义后缀的识别严格度（`_matches`）。
- **删除原贴图（Delete Source）**：开启后，处理成功会把源文件移入**回收站**（可撤销，见第 8 节），而非直接删除。
- **文件夹批量自动处理**：选择文件夹时，递归扫描所有图片，按"自定义后缀 + 匹配模式"自动判定每张图该用哪个处理器（`process_game2pbr_auto`）；并自动跳过"本身就是生成产物"的文件，避免重复处理。
- **选择指定图片**：用户可从待处理列表里按当前自定义后缀快速筛选勾选（`_select_matching_game_suffixes`）。
- **处理选中 / 处理全部**：分别只跑勾选项或跑当前列表全部（`_start_game2pbr_selected` / `_start_game2pbr_all`）。

## 3. PBR2DayZ 模块（标准 PBR 贴图组 → DayZ 引擎贴图）

**入口文件**：`processors/pbr2dayz.py`
**界面**：`ui/pages/pbr.py` 的 PBR2DayZ 页
**支持输入格式**：`.png .jpg .jpeg .tga .bmp .tif .tiff`（见 `IMAGE_EXTENSIONS`）
**输出格式**：`.tga`（如需 `.paa` 则再调 ImageToPAA 转换）

该模块把一组语义化的 PBR 贴图（颜色/法线/粗糙度/金属度/AO）转成 DayZ 的 4 类贴图：**co（颜色）/ nohq（法线）/ smdi（高光/光泽）/ as（环境遮蔽阴影）**。

### 3.1 PBR 类型识别

按文件名关键词识别 5 类贴图（`detect_texture_match`，关键词可在设置里自定义）：

| 类型 | 默认关键词 |
| ------ | ----------- |
| basecolor（颜色） | basecolor, base_color, albedo, diffuse,_color, _d,_bm_rgb,_rgb, _sg_bm_rgb,_mg_bm_rgb |
| normal（法线） | normal, _n, nrm, nrml,_mg_orn_n, _sg_orn_n, orn_n |
| roughness（粗糙度） | roughness, rough, _r,_mg_orn_rou, _sg_orn_rou,_orn_rou,_rou |
| metallic（金属度） | metallic, metal, _m,_sg_bm_alpha, _mg_bm_alpha,_bm_alpha,_alpha, _b,_mg_b,_sg_b |
| ao（环境光遮蔽） | ao, ambient, occlusion, _ao,_occ, _mg_orn_ao,_sg_orn_ao, _orn_ao |

- **匹配模式**：`exact` / `fuzzy` 两种（`_matches_keyword`），模糊模式对短关键词（≤3 字符）用边界正则避免误命中。
- **分组逻辑**：按"文件夹 + 前缀"把同组贴图归并为一个 `PBRGroup`（`_scan_pbr_paths`），缺失某类型贴图时对应输出自动跳过。

### 3.2 四类 DayZ 输出转换

| 输出 | 函数 | 转换逻辑 |
| ------ | ------ | --------- |
| **co**（颜色） | `convert_co_texture` | 默认直接输出颜色图；`co_mode=specular` 时按金属度图把"镜面反射色"从漫反射中剥离（公式 `spec = base*metal + (1-metal)*0.04`，`diffuse = base*(1-max(spec))`） |
| **nohq**（法线） | `convert_nohq_texture` | 直接拷贝法线；`normal_type=opengl` 时对 G 通道翻转（DirectX↔OpenGL 法线差异） |
| **smdi**（高光/光泽） | `convert_smdi_texture` | 由金属度+粗糙度合成：R=255，G=镜面强度 `(metal+(1-metal)*0.04)*specular*255`，B=光泽 `(1-rough)*glossiness*255` |
| **as**（环境阴影） | `convert_as_texture` | 由 AO 反相后合成：G=反相 AO，R/B=0，再整体反相（与 DayZ 的 AS 通道约定一致） |

> 注：这里的 smdi 是 PBR2DayZ 内部"由金属度+粗糙度合成"的路径；另有一个独立模块可直接把一张颜色贴图转成 SMDI 贴图（见第 5 节）。

### 3.3 模块级功能/开关

- **法线类型（Normal Type）**：`directx` / `opengl`，控制 nohq 输出是否翻转 G 通道。
- **分辨率（Resolution）**：`auto / 256 / 512 / 1024 / 2048`。`auto` 模式超过 2048 边自动等比缩放到 2048（`_resolution`）。
- **Co 模式（co_mode）**：`basecolor`（直出）/`specular`（剥离镜面高光，需配合金属度图）。
- **Specular / Glossiness 参数**：全局系数，影响 smdi 输出强度（默认 0.75 / 1.0）。
- **前缀规则（Prefix Rule）**：决定输出文件名前缀，5 种：
  - `auto`：用所在文件夹名（若文件夹名为 `data` 则用其父目录）
  - `current_folder`：当前子文件夹名
  - `parent_folder`：上级文件夹名
  - `filename_prefix`：从文件名里去掉匹配到的关键词前缀（`_filename_prefix`）
  - `custom`：固定前缀（用户自填）
- **生成 PAA（Generate PAA）**：开启后调用 `ImageToPAA.exe` 把 `.tga` 再转成 `.paa`；若生成成功会删除中间 `.tga`，只留 `.paa`（`_delete_tga_outputs_with_paa`）。
- **添加水印（Add Watermark）**：开启后对所有输出贴图嵌入盲水印（内容/密码取自设置，见第 4 节）。
- **删除原贴图（Delete Source）**：处理成功后将源 PBR 图移入回收站。
- **自定义识别后缀**：5 类贴图各自可配置关键词列表（设置页，`_load_pbr_suffixes`）。
- **自定义输出后缀**：co/nohq/smdi/as 各自可配置输出后缀（默认 `_co`/`_nohq`/`_smdi`/`_as`，设置页）。
- **处理选中 / 处理全部**：同 Game2PBR。

## 4. Watermark 模块（盲水印嵌入与提取）

**入口文件**：`processors/watermark.py`
**界面**：`ui/pages/mark.py` 的水印页
**支持格式**：`.png .jpg .jpeg .bmp .tif .tiff .tga .paa`（见 `SUPPORTED_WATERMARK_EXTENSIONS`）

基于 `blind-watermark` 库实现不可见盲水印，可对贴图嵌入一段文字，并凭密码+长度提取还原。

### 4.1 功能点

- **添加水印（Add Watermark）**：`add_watermark` —— 把指定文本内容以盲水印方式写入图片。
  - 普通格式（PNG/JPG/BMP/TIF）直接嵌入；
  - **TGA**：先转 PNG 嵌入再存回 TGA；
  - **PAA**：先调 `ImageToPAA.exe` 解码成 PNG → 嵌入 → 再编码回 PAA（需已配置 exe 路径）；
  - 密码支持数字或字符串（字符串经 SHA-256 派生为 int，`_password`）；
  - **覆盖源（Overwrite Source）**：开启则原地写入（`add_watermark_in_place` 用临时文件替换），否则输出 `_watermarked` 副本。
- **检测水印（Detect Watermark）**：`detect_watermark` —— 凭密码 + **水印长度（wm_bit 长度）** 从图片中提取原始文本。长度必须从设置或上一次添加时记录的值获得（界面会在添加后自动回填 `watermark_length`）。
- **水印内容 / 密码 / 长度**：全局配置，存于设置（见第 7 节）。
- **批量**：`add_watermark_files` / `detect_watermark_files` 支持多文件，带进度回调。
- **依赖缺失提示**：未安装 `blind-watermark` 时抛出明确错误提示先装 `requirements.txt`。

## 5. SMDI 模块（颜色贴图 → SMDI 高光贴图）

**入口文件**：`processors/smdi.py`
**界面**：`ui/pages/smdi.py` 的 SMDI 页
**支持输入格式**：`.png .jpg .jpeg .bmp .tif .tiff .tga .paa`（见 `SUPPORTED_SMDI_EXTENSIONS`；PAA 会先经 `ImageToPAA.exe` 解码）
**输出格式**：`.tga`，勾选"生成 PAA"后为 `.paa`

把一张**颜色贴图**（通常是 `_co` / `_ca`）按 DayZ 的 specular 滤镜算法转成 SMDI 高光贴图，对应 `ImageToPAA.exe` 滤镜脚本里的 `specularMapFinish`。与第 3.2 节 PBR2DayZ 的 smdi 输出是两条独立路径，互不依赖。

### 5.1 转换公式

对每个像素取源图的 `G`、`B` 通道（`R`、`A` 不参与计算，见 `convert_smdi_pixels`）：

| 输出通道 | 取值 |
| --------- | ------ |
| `R'` | `1 - G`（反相源绿通道） |
| `G'` | `G * ((sp * B + 1) / (sp + 1))` |
| `B'` | `B`（原样保留） |
| `A'` | `255` |

- `sp` 为高光强度参数，默认 10，越大越强调蓝通道对高光的影响。
- 取整方式与工具内部 `bitfilt` 一致：`floor(x * 255 + 0.5)`（四舍五入进位），**不是** numpy 的银行家舍入 `np.rint` —— 两者只在 `sp` 为奇数且结果恰好落在 `.5` 时有差异。
- 参考值（`sp = 10`）：源 `[200, 128, 64, 255]` → `[127, 41, 64, 255]`。

### 5.2 命名与输出

- 输出写在**源文件同目录**，文件名为 `<名字>_smdi.tga`（勾选"生成 PAA"时为 `.paa`）。
- 命名规则（`smdi_output_stem`）：文件名以 `_co` / `_ca` 结尾（不区分大小写，且去掉后仍有内容）时先去掉该后缀再拼 `_smdi`，否则直接拼 `_smdi`。例：`armor_co.png` → `armor_smdi.tga`；`armor.paa` → `armor_smdi.tga`。
- 同名输出**静默覆盖**，不做改名兜底；写入先落在临时目录再 `shutil.move` 到目标，因此不会把已存在的旧输出截断成半成品。
- 勾选"生成 PAA"时调用 `ImageToPAA.exe` 打包，成功后**删除同名的中转 `_smdi.tga`**，只留 `.paa`。
- **PAA 输出要求宽高都是 4 的倍数**，否则该文件失败并给出可读错误（`PAA output needs width and height to be multiples of 4, but <文件名> is <宽>x<高>.`）。PAA 内部是 DXT1 有损压缩，回解后 G/B 通道可能与 TGA 结果相差 1；`R` 与 `A` 会被 `*_smdi.*` 命名规则强制为 255。

### 5.3 模块级功能/开关

- **高光强度 sp（Specular Power）**：界面输入框，默认 10，随设置持久化（`settings.smdi_specular_power`）；必须是有限且 ≥ 0 的数字，非法输入会退回默认 10（`parse_specular_power` / `_save_smdi_settings`）。
- **生成 PAA（Generate PAA）**：勾选后直接输出 `.paa`，依赖设置页配置的 `ImageToPAA.exe` 路径。
- **输入含 PAA**：PAA 先用 `ImageToPAA.exe` 解码成 PNG 再参与计算，因此可以直接拿游戏里的 `_co.paa` 生成 SMDI。
- **拖拽 / 选择图片**：拖拽区支持单文件、多文件、文件夹（递归扫描），也可用文件对话框选择；按扩展名过滤并去重。
- **处理选中 / 处理全部 / 清除选中 / 全选 / 进度条 / 状态栏**：与其它处理页一致。
- **批量输出冲突防护**（`_batch_conflict`）：同一批里若某文件的输出会覆盖**同批的另一个输入文件**，或与前面文件产生**同一个输出**，该文件记为失败并给出原因（先到先得），避免批处理互相踩踏。
- **失败原因回显**：批量结果存在失败项时，状态栏在"成功/失败/跳过"汇总后追加第一条失败原因（`_append_smdi_failure`），而不是只显示失败数量。

## 6. RVMAT 模块（材质损坏变体）

**入口文件**：`processors/rvmat.py`
**界面**：`ui/pages/rvmat.py` 的 RVMAT 页
**支持输入格式**：`.rvmat`（DayZ 材质定义文本文件）
**输出格式**：`.rvmat`，写在**源文件同目录**

把一份 `.rvmat` 材质复制出 `_worn` / `_damage` / `_destruct` 三份损坏变体，每份只把 `class Stage3` 里的 `texture` 换成 DayZ 自带的通用损坏贴图，其他 Stage 一个字都不碰。这是独立小工具 `Rvmat-Creator` 的移植版，顺手修掉了原版的四个缺陷。

### 6.1 三个变体

| 变体后缀 | Stage3 指向的贴图（可在设置页改） |
| --------- | -------------------------------- |
| `_worn` | `dz\characters\data\generic_worn_mc.paa` |
| `_damage` | `dz\characters\data\generic_damage_mc.paa` |
| `_destruct` | `dz\characters\data\generic_destruct_mc.paa` |

后缀名固定不可改 —— DayZ 引擎按文件名找这三个变体。

### 6.2 替换规则

- 只认 `class Stage3` 之后的**第一行** `texture = "..."`，用**花括号配对计数**判断 Stage3 的结束，而不是原版"遇到 `};` 就退出"—— Stage3 里通常嵌着一个 `class uvTransform { ... };`，原版会提前退出。
- 只替换引号里的那一段，`texture` 关键字、等号两边的空格、缩进（通常是 Tab）、分号后面的内容**全部原样保留**。
- 换行符原样保留（CRLF 还是 CRLF，LF 还是 LF）。
- 编码自动识别：UTF-8 带不带 BOM 都认，认不出按 GBK 试；写回时保持原来的编码。
- 输出写在源文件同目录，文件名为 `<原名><后缀>.rvmat`；同名文件**直接覆盖**。
- 文件里没有 `class Stage3` 时**明确报失败**，三份候选产物一个都不落地。

### 6.3 页面交互

- **三个勾选框**（`_worn` / `_damage` / `_destruct`，默认全勾）：决定这次生成哪几份，不随设置持久化。
- **列表每行**：左边一格是源文件（非图片，格子里显示 `RVMA` 占位），右边**永远是三格**。格子里的大字是变体后缀，下面小字是产物文件名；没勾的那格是空槽（显示 `—`），让人一眼看出这一份不会被生成。
- **点格子**：用系统默认程序打开该 `.rvmat`（记事本之类），而不是弹图片预览窗 —— rvmat 是文本，预览窗读不出图。
- **排除名单**：文件名以 `_worn` / `_damage` / `_destruct` 结尾的文件**不当输入**，但仍会列在列表里并标成"跳过"，让人看见"为什么这行没跑"。名单可在设置页改。
- **拖拽 / 选择文件 / 选择文件夹**：拖文件夹进来递归扫子文件夹，只收 `.rvmat`，其他文件静默忽略。

### 6.4 相对 `Rvmat-Creator` 修掉的四个缺陷

| 原版行为 | 现在 |
| --------- | ------ |
| `texture = "..."`（等号带空格）匹配不到，静默生成一份和原文一样的副本还报成功 | 空格随便写都能认（实测语料里约 9% 的文件是这种写法） |
| 文件里没有 `class Stage3`，照样生成副本、照样报成功 | 明确报失败，写清原因，三份候选产物一个都不落地 |
| CRLF 文件里被替换的那一行丢掉 `
`，输出混换行符 | 换行符原样保留（实测语料 94% 是 CRLF） |
| 编码写死 UTF-8，GBK 文件直接抛错 | 自动识别，写回保持原编码 |

另外补了批量冲突防护：同一批里若某文件的输出会覆盖**同批的另一个输入文件**，该文件记为失败。被排除的变体不算输入，所以"源文件旁边已经躺着同名变体"这种常见情况不会误报。

### 6.5 模块级功能/开关

- **三个贴图路径**：设置页 RVMAT 区块可改，随设置持久化（`rvmat_damage_textures`）；路径里的 `/` 自动转成 `\`。
- **排除名单（Skip suffixes）**：设置页可改，随设置持久化（`rvmat_excluded_suffixes`），逗号或空格分隔；清空则所有 `.rvmat` 都当输入。
- **处理选中 / 处理全部 / 清除选中 / 全选 / 进度条 / 状态栏**：与其它处理页一致。

## 7. 设置模块（Settings）

**界面**：`ui/pages/settings.py` 的设置页
**持久化**：`settings.py:load_settings / save_settings` → `%APPDATA%/Roaming/DayZ_Texture_Tool/settings.json`

- **ImageToPAA.exe 路径**：指向 DayZ Tools 的 `ImageToPAA.exe`（PBR2DayZ 生成 PAA、Watermark 处理 PAA、SMDI 输入/输出 PAA 都依赖它）；提供浏览按钮。
- **水印默认项**：水印内容、水印密码、水印长度（供检测时回填）。
- **SMDI 高光强度**：sp 默认值（`smdi_specular_power`），随设置持久化。
- **RVMAT 损坏贴图路径**：三个变体（`_worn` / `_damage` / `_destruct`）各自指向哪张贴图（`rvmat_damage_textures`），默认是 DayZ 自带的 `dz\characters\data\generic_*_mc.paa`；输入框里写了 `/` 会自动转成 `\`。
- **RVMAT 排除名单**：文件名以这些后缀结尾的不当输入（`rvmat_excluded_suffixes`），默认 `_worn, _damage, _destruct`，逗号或空格分隔；清空则所有 `.rvmat` 都当输入。
- **中英语言切换**：顶部"English / 中文"按钮实时切换整个界面文案（见第 8.1 节）；切换时自动保存当前各后缀/匹配配置。
- **各模块后缀与匹配配置**：
  - Game2PBR：每种处理器的自定义识别后缀 + 各输出通道后缀
  - PBR2DayZ：5 类贴图识别关键词 + 4 类输出后缀 + 前缀规则/固定前缀
  - 匹配模式（Game 用 `exact` 默认，PBR 用 `fuzzy` 默认）
- **保存/自动保存**：设置页"保存"按钮显式保存；关闭窗口、切换语言、切换处理器/匹配模式时也会自动 `save_settings` 落盘。
- **配置合并策略**：加载时以默认值为底、用户 JSON 覆盖，保证新增默认项不会因旧配置缺失而报错（`_merge_suffixes` 等）。

## 8. 通用能力（横跨所有模块）

### 8.1 中英双语界面

- 英文原文写在代码里（`self.tr(...)`），中文译文在 `ui/translations/dayz_zh_CN.ts`，编译成 `dayz_zh_CN.qm` 随包发布。
- 界面文字全部走 Qt 翻译系统，切换零重启、即时刷新（`MainWindow.apply_language`）；默认语言是英文，漏翻只会退回英文。
- 逻辑层写死的提示也用 `QCoreApplication.translate` 套了一层，没装翻译器时原样返回英文。

### 8.2 拖拽上传

- 四个处理页都支持拖拽（Qt 原生 `dragEnterEvent` / `dropEvent`，不需要额外库）。
- Game2PBR / PBR2DayZ：可拖入单文件、多文件、文件夹（文件夹递归扫描）；
- Watermark：可拖入文件或文件夹，支持 PAA。
- 拖入后自动去重、按扩展名过滤、填充待处理列表。

### 8.3 异步处理 + 进度条

- 所有批量处理在后台线程池执行（`QThreadPool` + `QRunnable`，单线程串行），不卡 UI。
- 每处理完一条通过信号回主线程刷新那一行（`Job` / `WorkerSignals`），底部状态栏同步百分比进度。
- 完成后状态栏显示“完成 X · 失败 Y · 跳过 Z”，出问题的行会汇总到列表下方的“问题”面板。

### 8.4 回收站删除（可撤销）

- `recycle.py:move_to_recycle_bin` 通过 `ctypes` 调用 Windows `SHFileOperationW`（带 `FOF_ALLOWUNDO`），把"删除原贴图"的文件移入系统回收站而非永久删除，误操作可还原。

### 8.5 批量跳过 / 错误处理

- 无匹配后缀、已是生成产物、文件缺失等情况记"跳过"（skip），不计入失败；
- 单个文件异常被捕获并记"失败"（fail）+ 错误信息，不影响其余文件（`ProcessingResult` / `BatchResult` 模型，见 `models.py`）。

### 8.6 统一结果模型

- `ProcessingResult`（单文件：成功/输入/输出/处理器/耗时/错误/消息/元数据）；
- `BatchResult`（批量：累计总数/成功/失败/跳过、总耗时、合并输出列表），供 UI 汇总展示。

## 9. 测试与打包

### 9.1 测试

- `tests/` 下 unittest 用例：`test_batch_settings`、`test_game2pbr`、`test_pbr2dayz`、`test_rvmat`、`test_smdi`、`test_ui_pages`、`test_watermark`，覆盖各处理器像素逻辑、批量/匹配、界面拖拽与分组、设置合并。
- 装齐 `requirements.txt` 依赖后全量 `python -m unittest discover -s tests` 共 **142 个用例全部通过**（裸环境下缺 `PySide6` / `blind-watermark` 时会分别表现为导入错误与用例失败）。
- 打包脚本 `package.ps1` 默认在构建前跑 `python -m unittest discover -s tests`。

### 9.2 打包发布

- `DayZ_Texture_Tool.spec` 为 PyInstaller 配置（one-folder 风格，输出到 `dist/`）。
- `scripts/package.ps1` 一键流程：建/用 venv → 装 PyInstaller → 装本项目 → 跑测试 → 清旧构建 → `pyinstaller` 构建 → 拷贝到 `release/DayZ_Texture_Tool/` → 可选压缩为 zip。
- 支持参数：`-Python <path>`、`-SkipTests`、`-NoClean`、`-NoZip`。
- 分发时要整个目录一起给（one-folder 模式，依赖都在 `_internal/`），即 `release/DayZ_Texture_Tool.zip`。
